# Архитектура RaspoznanieTeksta

Курсовая работа: распознавание рукописных букв, цифр и математических формул,
нарисованных мышкой на холсте. Два движка машинного обучения объединены в ансамбль.
Организация повторяет проверенную схему Microsoft «Ink to Math»: штрихи как
объекты → классификация символов → двумерный структурный разбор → уравнение
(в нашем случае MathML, который Word превращает в нативное уравнение).

## Схема потока данных

```
Холст (модель штрихов)
   │  getImage(): рендер штрихов в прозрачный растр
   ▼
ImageProcessor
   ├── extractFeatures(): обрезка → масштаб 20×20 → 400 признаков (альфа/255)
   ├── segmentSymbols(): колонковая сегментация + склейка «=»/«+» + разрезание
   │   слипшихся символов (splitWide) — для линейного пути и окна кандидатов
   └── segmentComponents(): связные компоненты (BFS 8-связность) — для 2D-разбора
   │
   ├──► RecognitionEngine (kNN): взвешенное голосование 3 соседей + центроиды
   │
   ├──► NeuralEngine (DL4J): MLP 400→256→128→softmax(113)
   │
   └──► FormulaLayout (только для формул): 2D-разбор → линейная строка
        со структурой: «(1)/(2)», «x^(2)», «x_(1)», «√(x+1)»
   ▼
EnsembleEngine: итог = произведение долей NN × kNN, ренормализация топ-5
   ▼
UI: результат + строка деталей («Нейросеть: … • kNN: … • движки согласны»)
   ├── «∑ В Word»: MathMlBuilder → MathML → буфер (Word: Вставка → Уравнение → Ctrl+V)
   └── «📷 Фото»: обрезка → масштаб → картинка в буфер
```

## Модули

### ImageProcessor — обработка изображения

- `extractFeatures(BufferedImage)` — обрезка до содержимого (по альфа-каналу,
  порог > 10), масштаб до 20×20 билинейной интерполяцией, вектор из 400 значений
  `альфа/255`. Формат признаков менять нельзя без миграции базы (см. ниже).
- `segmentSymbols(img, gap)` — колонковая сегментация: пустые столбцы шириной
  `gap` (3 px) делят холст на фрагменты. Поверх — две поправки:
  - `mergeMultiStroke` — склейка многоштриховых знаков, нарисованных с отрывом
    пера: «=» (две плоские полосы друг над другом, нахлёст до 35%) и «+»
    (вертикальный штрих сквозь/вплотную к горизонтальной полосе);
  - `splitWide` — разрезание слипшихся символов (aspect > 1.7) по самому тонкому
    столбцу средней трети, рекурсивно.
- `segmentComponents(img)` — сегментация по связным компонентам чернил
  (BFS 8-связность). Основа 2D-разбора: содержимое дроби, стоящее друг над
  другом, остаётся раздельными боксами. Сюда же — `mergeDiacritics`: точка «i»
  приклеивается к своему штриху (мелкий бокс над крупным, по центру).
- `Box` — фрагмент с координатами и вырезанной картинкой (паддинг 2 px).

### FeatureOps — нормализация признаков

`smoothAndCenter`: сглаживание ядром 3×3 + центрирование по центру масс.
Применяется одинаково к образцам базы (при добавлении) и к распознаваемому
рисунку — это дало +19 п.п. к kNN в 4-fold CV и подняло устойчивость к сдвигу
на 1 px с 58% до 83%. Дескью (выравнивание наклона) реализован, но в конвейер
не включён: на шрифтовой базе он снижает точность.

### RecognitionEngine — kNN («машинное обучение»)

Хранит образцы (метка + 400 признаков). Распознавание: 3 ближайших соседа по
евклидову расстоянию голосуют с весом `1/(1+d)`, плюс «якорный» голос центроида
каждого класса (вес 0.5). Уверенность кандидата — доля голосов среди топ-5.

Два файла базы:
- `data/samples.dat` — синтетическая база SampleGenerator (только чтение);
- `data/samples_user.dat` — образцы пользователя, автосохранение при «Обучить».

Формат v2 (`SampleBase`): признаки уже нормализованы. Старые файлы
(`List<Sample>` с сырыми признаками) нормализуются при загрузке — полная
обратная совместимость, включая рукописную базу 147 образцов из
`data/samples_backup_old.dat`.

### NeuralEngine — нейросеть (Deeplearning4j)

MLP 400 → 256 (ReLU) → 128 (ReLU) → softmax(113). Adam 0.01, XAVIER, батч 64,
перемешивание данных каждую эпоху (без этого класс-упорядоченные данные
схлопывают сеть), dropout не используется (экспериментально убивал сходимость).
Обучается на аугментированных копиях: сдвиг ±1 px, повороты ±6°/±12° (знаки
менее), масштаб 0.92/1.08 — ×2 к объёму. Переобучение — в фоновом потоке после
каждого «Обучить» и при загрузке базы (~60–90 с на текущем объёме).

### EnsembleEngine — ансамбль

Итоговая оценка кандидата = произведение долей нейросети и kNN
(`nn(l) × knn(l)`). Вознаграждает согласие движков, штрафует расхождения:
по эксперименту 57% против 54% (kNN) и 48% (NN) по отдельности на holdout.
Выбор способа слияния сделан по результатам сравнения: взвешенные доли
(52–56%), RRF (56%), произведение (57%).

### FormulaLayout — 2D-разбор формул «как в Word»

Работает по `segmentComponents`. Этапы:

1. **Дробная черта**: плоский бокс (aspect ≥ 2.2), под которым и над которым
   есть содержимое с перекрытием по x. Числитель и знаменатель разбираются
   рекурсивно → «(числ)/(знам)».
2. **Радикал**: черта с содержимым только снизу и высокой «галочкой» слева
   вплотную (метка галочки не важна — √ и v по форме совпадают, решает
   структура) → «√(содержимое)».
3. **Степень/индекс**: цепочки боксов высотой ≤ 0.7 от базы, справа-сверху →
   «base^(exp)», справа-снизу → «base_(sub)». Одиночный оператор в позиции
   степени — линейно (защита от «оторвавшихся» точек и маленьких звёздочек).
4. Остальное — линейная последовательность.

Результат — линейная строка со структурой в скобках, плюс параллельные строки
ответов каждого движка (для строки деталей).

### MathMlBuilder — линейная строка → MathML

Токенизация: числа (с десятичной запятой), буквы (ряды-функции sin/cos/tg/
ctg/log/ln/lim/sqrt — одним `<mi>`), операторы (`*` → `⋅`, `<` → `&lt;`),
скобки → `<mrow>`. Затем свёртки: `^` → `<msup>` (базой считается весь
предшествующий ряд букв — `sin^2` даёт `(sin)²`, а не `n²`), `_` → `<msub>`,
`/` → `<mfrac>` (в этом порядке: `x^2/3` → дробь с `x²` в числителе), `√` →
`<msqrt>`. Редактор уравнений Word принимает MathML из буфера и превращает
в нативное уравнение.

### UI (MainFrame)

- Слева — функции распознавания: Обучить, Распознать символ, Распознать строку,
  Динамически (автозапуск разбора через 700 мс после паузы в рисовании),
  Фото, В Word.
- Тулбар — инструменты (Карандаш/Ластик/Выделить/Очистить/Удалить выдел.) и
  настройки (язык RU/EN, режим Цифры/Буквы/Оба/Формулы, регистр, базы).
- Внизу — статус, результат ансамбля, строка деталей обоих движков.
- Холст — модель штрихов: каждый штрих объект с точками, ластик удаляет штрих
  целиком, стёртое исчезает физически (раньше ластик рисовал белым непрозрачным,
  а распознавание читало альфа-канал — «стёртые» линии оставались «чернилами»).

## Режимы и фильтры

Режим задаёт допустимые метки (фильтр применяется и к базе, и к ответам):
- Цифры: `0-9`; Буквы: кириллица или латиница (заглавные);
- Цифры+Буквы: объединение; Формулы: цифры, `+ - * / = ( ) ^ . , < > | √ π ≤ ≥ ≠`
  и строчные латинские буквы (заглавные исключены сознательно: у шрифтов x и X
  неразличимы по форме, в формулах стандарт — строчные).

Фильтр также снимает путаницу кириллицы с латиницей (О↔O, У↔Y): в режиме
«Буквы (RU)» латинские близнецы исключаются из кандидатов.

## Тестирование

Headless-тесты (запуск через `java` с classpath `target/classes` + зависимости):

| Набор | Что проверяет | Результат |
|---|---|---|
| TestSuite seg | сегментация строк, широкие W/M не режутся, слипшиеся режутся, пустой холст | 7/7 |
| TestSuite feat | пусто→null, длина 400, диапазон [0,1], детерминированность | 5/5 |
| Formula2DTest | дробь 1/2, дробь a/b, степень x², a+=2 штрихами, sin(x), √9, √(x+1) с чертой, sin²(x), \|x\|, π*r | 10/10 |
| StrokeLineTest | штриховая строка a+=2, sin(x) | PASS |
| DrawPanelTest | ластик удаляет штрих целиком, стирание без «призраков», Delete по выделению | 4/4 |

Известные ограничения: символы, нарисованные вплотную (без пустых столбцов),
уходят в один фрагмент (лимит вертикальной проекции); `o`/`0` и `|`/`l`
неразличимы по форме — выбор в окне кандидатов.
